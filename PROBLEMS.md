# Problems and Lessons

A record of real problems hit while building PolicyLens, how each was diagnosed and fixed, and what was learned. Planned challenges are listed separately at the end.

## Problems encountered

| Date | Problem | Cause | Resolution | Lesson |
|---|---|---|---|---|
| 21 Oct 2026 | `docker` not recognized in PowerShell | The terminal was opened before Docker was installed, so its PATH was stale. | Added the Docker folder to PATH for that session; restarting the terminal fixes it permanently. | A new install is not visible to terminals that were already open. |
| 21 Oct 2026 | `pytest` failed with "No module named 'src'" | Tests were run from the parent folder, not the project root, so the configured import path was not applied. | Changed into the project folder before running tests. | Run tools from the project root, and check the working directory first. |
| 21 Oct 2026 | Loader tests were missing | `test_loaders.py` was empty, and later held loader code instead of tests. | Replaced it with the correct tests and re-ran the suite. | Confirm a file's contents after saving it, not just that it exists. |
| 22 Oct 2026 | First commit failed after the formatter ran | The ruff-format hook rewrote files and stopped the commit, so the next push reported "Everything up-to-date". | Staged the reformatted files and committed again. | If a hook modifies files, re-add and recommit before pushing. |
| 22 Oct 2026 | `git` reported "not a repository" | Commands were run from the workspace folder above the project. | Changed into the project folder and re-ran them. | Check the prompt's folder before running Git commands. |
| 22 Oct 2026 | Git tag pointed at the wrong commit | The commit, push and tag commands were pasted together. The hook stopped the commit, but the tag command still ran on the previous commit and was pushed. | Moved the tag with `git tag -f` and updated it on GitHub with a forced tag push. | A failed commit does not stop later commands. Run them one at a time and confirm the commit before tagging. |
| 22 Oct 2026 | Search demo raised `FileNotFoundError` | The sample file was inside a nested `samples/samples` folder. | Moved the file up one level and removed the empty folder. | Confirm exact paths with `dir` before running a script that reads files. |
| 22 Oct 2026 | Embedding model download stalled | On a slow connection the download paused at the file-assembly step. | Stopped the run, disabled the fast-download helper for that session, and restarted. Partial downloads were reused. | Check whether bytes are still moving before retrying, and know the fallback. |
| 22 Oct 2026 | Search ranked a less relevant chunk first | Chunks were small (20 words), cut across sentences, and a loosely related chunk shared the word "days" with the question. The best chunk ranked second. | Not fixed. Recorded as a limitation. Chunk size has not yet been tested systematically. | Measure retrieval quality before building answer generation on top of it. |
| 23 Oct 2026 | `python -m scripts.ask_demo` could not find the script | I saved `ask_demo.py` inside `.venv\Scripts` instead of `scripts`. | Found it with `Get-ChildItem -Recurse` and moved it into `scripts`. | Check the folder before saving. The virtual environment is not part of the project. |
| 23 Oct 2026 | The terminal waited for more input after `git commit -m` | The commit message had no closing quote. | Pressed Ctrl+C and re-ran the command with both quotes. | If the prompt shows `>>` and nothing happens, check for a missing quote. |
| 23 Oct 2026 | A refused answer still listed sources | The code returned the retrieved chunks whatever the model said. | Wrote a failing test first, then added a check that returns no sources when the reply starts with "I don't know". | Refusal text and sources must agree. The check depends on the model's wording, which is a known limitation. |
| 23 Oct 2026 | The first run looked stuck and I interrupted it (KeyboardInterrupt) | The embedding library is slow to import and load the first time. | Ran it again and waited. | Give heavy model imports time before assuming a hang. |
| 23 Oct 2026 | Ollama install command failed with "Installer signature verification failed" | The install script's signature check did not pass on my machine. | Did not bypass the check. Installed Ollama from the website and confirmed with `ollama --version`. | Do not bypass a security check to make an install work. |
| 24 Oct 2026 | Unrelated questions still retrieved text | FAISS always returns the nearest chunks, so only the model's wording stopped a wrong answer. | Added a `min_score` cutoff, measured real scores, compared cutoffs on 11 labelled questions, and chose 0.15 as a starting value. | Choose thresholds from measured scores. The sample is small, so the cutoff must be re-tested on real documents. |
| 24 Oct 2026 | 4 answering tests failed with `FakeStore.search() takes from 2 to 3 positional arguments but 4 were given` | `TenantStores` now always passes `min_score` to the store, but the fake store in `test_answering.py` accepted only two arguments. I had expected the old fake to keep working. | Updated the fake's `search` signature to accept `min_score`. | When an interface changes, update every fake that follows it. The failing tests found the mismatch. |
| 29 Oct 2026 | With two return policies (30 and 15 days), the model answered "I don't know." | Both sources were retrieved, but the prompt gave no way to tell which was newer, and the model refused. I confirmed this by printing the prompt instead of calling the model. | Added version and date to each source line and an instruction to prefer the newest source when sources disagree. It improved but was not reliable. | Print the prompt to find out whether retrieval or the model is the cause before changing anything. |
| 29 Oct 2026 | Normal answers started mentioning an "older source" that did not exist | The "prefer the newest" instruction was in every prompt, so the model applied it to chunks from the same file. | Added the instruction only when `find_competing_sources` flags more than one file, with a test for both cases. | After changing a prompt, rerun the earlier demos to check for side effects. |
| 29 Oct 2026 | A push appeared to succeed but did not include my latest change | The commit failed because the formatter hook reformatted files, but the push command still ran and pushed the earlier commits. | Re-ran `git add` and `git commit`, confirmed the commit hash, then pushed again. | Check for the commit hash before pushing. Paste commit and push as separate steps. |
| 29 Oct 2026 | With two conflicting return policies, the model sometimes called the older 30-day policy the newest and answered 30 days | The small model had to work out which source was newest from the dates in the prompt. | Marked the newest source in the prompt. My first before and after numbers (2 of 5 correct, then 5 of 5) were later withdrawn, see 30 Oct. | Let code decide what it can and give the model the result. |
| 29 Oct 2026 | Uploading a file on the API's `/docs` page returned a 422 error saying it expected a file but received a string | The generated docs page showed a text box for the list of files instead of a file picker, so it sent text, not my file. | Uploaded with `curl.exe` against the same running server, which returned 200 and the right file name and chunk count. The automated tests had already uploaded real files through the test client. | When one client fails, try a second before blaming the code. |
| 29 Oct 2026 | `curl` said it could not connect to the server | I started the server and ran `curl` in the same window. Uvicorn takes over the terminal, and once I stopped it or typed again the server was off. | Ran the server in one window and `curl` in a second one. | A server needs its own terminal for as long as it runs. |
| 29 Oct 2026 | An upload with one good file and one unsupported file would leave the good file in the store | `ingest_files` added each file as it was loaded, so an error on a later file left an earlier one behind. | Wrote a failing test first, then changed `ingest_files` to load every file before adding any. The API returns a 400 error for unsupported types. | Make multi-step changes all-or-nothing, and test the failure path. |
| 30 Oct 2026 | My "newest source" experiment looked successful, but both sample files had the same date | The command line took each file's date from its modified time, and I had saved both samples on the same day, so "newest" was decided by search order. | Added explicit dates (`--file path@YYYY-MM-DD`), withdrew the earlier before and after numbers, and reran with real dates and with the dates swapped to separate the label from the position. | Check what the data actually contains before trusting a result. A test can pass for the wrong reason. |
| 30 Oct 2026 | A reply cited only the 30-day source while claiming 15 days, and was still marked verified | The citation check only tests that a cited number exists, not that the source supports the claim. | Documented the limit and described `verified` as "cites a real source". | Name checks for what they actually prove. |
| 30 Oct 2026 | On three real university PDFs, the first run answered 6 of 10 questions correctly. I wrote the questions and expected answers before running. | Several separate causes, tested one at a time in the rows below. | Partly fixed. 9 of 10 and 8 of 10 in two later runs. | My own sample files hid these failures. Test on real documents early. |
| 30 Oct 2026 | "Can I..." questions (Q7 childcare, Q8 first-class rail) got "I don't know" although the answer sentence was the top-ranked chunk. | Not the similarity cutoff (switched off, no change). Not the refusal wording (reworded, 0 of 6 fixed). Not the other chunks (only one chunk given, 0 of 12 fixed). The 3B model refuses yes/no questions whose answer is "not permitted". | Prompt now says "Start your answer with Yes or No, then give the rule" for questions that begin with Can, Is, Do and similar words. Q7 and Q8 were then right in 4 of 4 runs. | Change one thing at a time. Telling the model to decide when to say Yes or No put "Yes" before "four months", so the code decides, not the model. |
| 30 Oct 2026 | Q6 (appeal deadline) is still wrong. The sentence with "10 working days" ranked 5th of 8, but only the top 3 reach the model. | Ranking. Chunks of 100 words instead of 200 were tried, with no reliable gain (0 of 2), so I did not adopt them. | Not fixed. | A result with 2 runs is a hint, not a finding. |
| 30 Oct 2026 | Q4 prints page 6, but the sentence is on page 5. | The model sometimes cites a neighbouring chunk. The verified flag only checks that the cited number exists, so it cannot catch this. | Not fixed. | The printed page is something to check, not something to trust. |
| 30 Oct 2026 | A chunk-size experiment gave identical chunk counts for both sizes. | I changed the defaults of the wrong function, so the setting was ignored. | Ignored that run, found the right place, reran. | Check that a change took effect before reading the result. |

## Challenges ahead

These are planned, not yet encountered. Each one should end in a reproducible test.

| Challenge | Why it matters | Planned approach | Planned validation |
|---|---|---|---|
| Preserving PDF page-level traceability | Wrong page metadata makes citations point to the wrong place. | Carry page numbers through extraction, chunking and retrieval. | Test multi-page PDFs against their original pages. |
| Handling malformed and partially readable documents | One corrupted file should not crash a whole ingestion batch. | Validate file types and handle parsing errors per document. | Test empty, malformed, unsupported and partly readable files. |
| Checking that cited sources support the claim | A citation can point to a real source that says something else. | Compare the cited passage with the claim, and flag mismatches. | Test replies that cite the wrong source. |
| Maintaining citations through chunking | Overlapping chunks can cause duplicated or incomplete citations. | Attach source and page metadata to each chunk and return it with results. | Check citations on documents with repeated text. |
| Detecting conflicting policy statements | Two documents can disagree because of version changes or different scope. | Compare relevant passages with document dates and versions before flagging. | Test known conflicts and cases that only look contradictory. |
| Keeping ingestion repeatable | Re-ingesting a document can create duplicate chunks. | Use stable document IDs and content hashes with explicit re-ingestion rules. | Ingest the same file twice and check the record counts. |
| Controlling resource use for large documents | Large PDFs can increase memory use and processing time. | Process incrementally, configure chunk sizes and set file-size limits. | Benchmark representative sizes for time and memory. |

Principle: a fix is complete only when the relevant test passes and the expected behavior is documented.
